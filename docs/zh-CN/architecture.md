# 架构与安全模型

[English](../architecture.md) | [简体中文](architecture.md)

## 设计目标

系统把券商与行情数据转换为可解释的决策辅助，但绝不跨越到自动执行。每条建议都必须保留输入、规则版本、数据时间与质量状态。

## 主数据链路

```text
IB Gateway（只读）
        │
        ▼
同步与调度器
        │
        ├── 账户 / 持仓 / 成交 / PnL
        ├── 行情质量与历史日线
        ├── 市场环境与技术指标
        └── 数据质量检查
        │
        ▼
dashboard.db
        │
        ├── 风控规则与联合事件
        ├── 建议合成
        ├── 持仓计划与执行匹配
        ├── 收益 / 重放 / 研究
        └── FastAPI + Jinja2 看板
```

账户事实始终以 IBKR 为准。Futu OpenD 只能提供报价和历史 K 线，不能提供余额、持仓、成交或 PnL。

## 进程隔离

| 进程 | 职责 | 外部写入 |
|---|---|---|
| `ib-gateway` | 启用 Read-Only API 的券商会话 | 不向券商写入 |
| `sync` | 摄取、校验、规则、建议与调度任务 | 本地数据库与通知 |
| `web` | 看板与 JSON API | 用户在本地创建的计划、日记与事件状态 |
| `hyperliquid` | 可选公共数据采集与影子验证 | 仅写 `hyperliquid.db` |
| `backup` | SQLite 在线备份与完整性检查 | 本地备份目录 |
| `caddy` | TLS 与反向代理 | 仅证书状态 |

## 券商只读边界

系统通过多层约束保护券商账户：

1. 客户端使用 `readonly=True` 连接；
2. Gateway 容器设置 `IB_READONLY=yes`；
3. API 中不存在下单、撤单、行权或转账路由；
4. 建议和机会采纳只创建本地草稿；
5. 测试持续检查下单端点与副作用不存在。

部署时还应使用专门的 IBKR 只读子用户。即使应用层约束回归，券商权限仍能保护账户。

## 先验证数据，再解释结果

系统宁愿明确显示未知，也不生成看似精确但缺乏证据的数字。

- 账户未就绪时不写零快照；
- 过期或冻结行情不能证明止损“安全”；
- 延迟行情可以支持较低等级提醒，但不能升级为最高紧急度；
- 历史重放只能读取当时已经存在的信息；
- 同批账户、持仓和行情共享 `sync_run_id`；
- 可选数据源独立降级，不能覆盖 IBKR 权威事实。

## 财务口径

三种盈亏不能相加：

- 当日盈亏：当前交易日的变化；
- 已实现盈亏：平仓成交已经落袋的结果；
- 未实现盈亏：开放持仓在某一时点的累计价值。

三种计数不能相互替代：

- order：一次券商指令；
- execution：一条成交回报，包含部分成交；
- decision：一次人工风险决策，可以包含多条成交。

资金流来自 Flex Query 或人工明确登记。系统不会根据无法解释的净资产变化反推入金或出金。

## 建议合成

建议综合以下信息：

- 组合与单仓风险；
- 市场环境与技术结构；
- 止损质量与行情质量；
- 当前持仓计划与冷静期；
- 指向具体评估记录的 provenance。

硬性风险动作优先于软性技术证据。缺失或过期依赖只能降低置信度或阻断判断，不能悄悄把风险动作变成正向建议。

## 机会模块

机会服务分阶段启用：

1. `OPPORTUNITY_ENABLED` 采集并评分候选；
2. 成功且非空的影子交易日累计就绪证据；
3. 达到最小影子门槛后，`PORTFOLIO_BUILDER_ENABLED` 才允许生成风险预算提案；
4. 采纳只创建本地草稿，不执行券商操作。

## Hyperliquid 隔离

Hyperliquid XYZ 是可选研究链路，使用独立数据库和调度执行器。采集、钱包会计、资产映射、PIT 群体、信号结果与验证都有独立版本。

晋级生命周期为：

```text
SHADOW → ELIGIBLE → ACTIVE
                    └──→ SUSPENDED
```

`ACTIVE` 必须具有样本外证据并获得人工批准。即使晋级，链上证据也只能收紧现有建议，不能创造交易或放松风险动作。

## 存储与恢复

- `dashboard.db` 保存主账户、风险、计划与复盘状态；
- `hyperliquid.db` 保存可选公共数据研究状态；
- 两个数据库都使用 SQLite 在线备份与完整性检查；
- 运行时数据库、备份、日志、凭据与生成报告不会进入公开仓库。

## 信任边界汇总

| 边界 | 允许 | 禁止 |
|---|---|---|
| IBKR | 读取余额、持仓、成交、PnL 与行情 | 下单、改单、撤单、行权或转账 |
| 本地应用 | 保存计划、日记、确认与派生分析 | 把本地草稿当成券商执行 |
| 可选行情源 | 带来源提供报价与 K 线 | 覆盖 IBKR 账户事实 |
| AI-compatible 简报服务 | 改写已经验证的结构化上下文 | 编造数字、绕过校验或阻断确定性模板 |
| Hyperliquid 研究 | 采集公共数据并生成影子证据 | 未经验证和人工批准影响生产 |
